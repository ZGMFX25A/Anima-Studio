## 1. 架构与启动

```
start.bat ──► 前端服务 frontend（127.0.0.1:8200，兼任进程管理）
                ├─ ComfyUI 引擎   127.0.0.1:8188   ← 菜单中可启动/停止/重启
                └─ 绘画模块 painter 127.0.0.1:8190
浏览器 ──► 前端服务：静态页面 + /api/*（代理绘画模块、图库、系统管理、LLM）
```

- **运行环境**：前端与绘画模块运行在根目录 `.venv`（依赖见根目录 `requirements.txt`，安装步骤见根目录 `README.md`）；ComfyUI 仍用 `ComfyUI_windows_portable\python_embeded` 自带 Python。
- **页面技术**：原生 HTML/CSS/JS（ES Modules），无 npm、无构建，离线可用；改完刷新即生效。
- **start.bat**（根目录）：调用前端服务入口，前端服务负责：
  1. 依次启动 ComfyUI → painter → 自身 HTTP 服务，轮询健康检查，全部就绪后自动打开浏览器；
  2. 控制台显示各服务状态；子进程意外退出时提示；
  3. **按 Enter**：有序关闭（前端 → painter → ComfyUI，超时强杀）；
  4. **直接关闭窗口**：所有子进程挂在 Windows Job Object（`KILL_ON_JOB_CLOSE`）上，随之一起结束，不留后台进程。
- **日志**：`logs\comfyui.log`、`logs\painter.log`、`logs\frontend.log`、`logs\llm_last_request.json`。

### 目录结构

```
F:\AI-Image-Generation\
├─ start.bat
├─ frontend\
│  ├─ DESIGN.md
│  ├─ server\            # 前端服务（进程管理、代理、图库、LLM）
│  ├─ web\               # 页面（index.html / css / js）
│  ├─ prompts\           # 发给 LLM 的全部提示词片段（见 §6.7）
│  ├─ config\            # 模型推荐范围、默认 neg 等前端配置
│  ├─ data\              # settings.json、gallery.db、refs\（运行时生成）
│  └─ logs\
└─ painter\              # 绘画模块（不改动）
```

## 3. 绘图页

### 3.1 模型与采样

- **模型**下拉：anima-base / anima-aesthetic / anima-turbo / anima-2.9b-preview / anima-2.9b-turbo-fuse（来自 painter `/v1/capabilities`）。
- 切换模型 → `steps`、`cfg` 自动重置为该模型默认值；输入框旁小字显示推荐范围，超出范围变警示色（不阻止提交）。

| 模型 | 推荐 steps | 推荐 cfg | 默认 | 来源 |
|---|---|---|---|---|
| anima-base | 30–50 | 4–5 | 30 / 4.0 | circlestone-labs/Anima 官方卡（通用建议） |
| anima-aesthetic | 30–50 | 4–5 | 30 / 4.0 | 同上 |
| anima-turbo | 8–12 | 1 | 10 / 1.0 | 官方卡："CFG 1，8–12 步" |
| anima-2.9b-preview | 28–50 | 3.5–5 | 30 / 4.0 | Gazingstars123/Anima-2.9B 作者卡 |
| anima-2.9b-turbo-fuse | 8–12 | 1 | 10 / 1.0 | Langzaigg/anima29b-turbo1.1-unofficial 作者卡（euler_ancestral + normal，不用负向） |

  推荐范围写在 `frontend/config/models_ui.json`，不改 painter 的 `models.json`。
- **cfg = 1 时**：`neg` 区域置灰，注明"cfg=1 时负向提示词不生效"。
- 模型的 `notes`（实测说明）作为悬浮提示展示。

### 3.2 提示词字段

| 字段 | 中文 | 控件 | 规则 |
|---|---|---|---|
| `quality_meta_year_safe` | 质量/元数据/年份/安全 | 单行文本 | 无校验（安全词非必选，不做按钮）。示例占位：`masterpiece, best quality, highres, newest, year 2025, sensitive` |
| `aspect_ratio` | 画幅比例 | 下拉 + "自定义" | 见下表，约 1MP、16 的倍数；旁边显示实际宽高；"自定义"时才可手填宽高 |
| `count` | 人数 | 文本 + 常用候选 | 1girl / 2girls / 1boy / 1other 等 |
| `character` | 角色 | 文本 | 如 `yunli (honkai star rail)` |
| `series` | 作品 | 文本 | 如 `honkai star rail` |
| `artist` | 画师 | 文本，默认空 | 每项须以 `@` 开头，不符合标黄并提供"补上 @"；多画师时提示"稳定性会下降" |
| `appearance` | 外貌 | 多行 | 发型、发色、瞳色、服装、配饰 |
| `action` | 动作 | 多行 | 动作、姿势、朝向、表情 |
| `nltags` | 自然语言 | 多行 | 英文自然语言描述，作为通用标签提交 |
| `neg` | 负向提示词 | 多行，预置默认模板 | 见下 |

**比例预设**（默认 2:3）：

| 比例 | 宽×高 | 比例 | 宽×高 |
|---|---|---|---|
| 21:9 | 1568×672 | 9:21 | 672×1568 |
| 16:9 | 1360×768 | 9:16 | 768×1360 |
| 3:2 | 1248×832 | 2:3 | 832×1248 |
| 4:3 | 1152×864 | 3:4 | 864×1152 |
| 5:4 | 1120×896 | 4:5 | 896×1120 |
| 1:1 | 1024×1024 | 自定义 | 256–2048，16 的倍数 |

**正向提示词拼接**（页面不展示拼接结果）：
`quality_meta_year_safe, count, character, series, artist, appearance, action, nltags`
空字段跳过；去除首尾空白与多余逗号。

**默认 neg 模板**（存于 `frontend/config/defaults.json`，可改）：
`worst quality, low quality, score_1, score_2, score_3, artist name, blurry, jpeg artifacts, chromatic aberration, bad anatomy, bad hands, extra fingers, missing fingers, extra limbs, deformed, text, watermark, logo, signature`

### 3.3 参考（人物 / 动作）

- 两个开关：**人物参考**、**动作参考**。开启后同一区域出现对应上传框（点击选择或拖入；另支持 Ctrl+V 粘贴），两者都开则并排。
  - 人物参考：1~3 张（推荐 全身 + 脸部特写），缩略图可单张移除。
  - 动作参考：1 张；类型选择 照片（自动检测骨架）/ 骨架图。
- 参考的细项参数（人物 strength、起止区间；动作 strength、fit、margin、persons、hands/face/feet）放在折叠的"参考高级"，默认值同 painter。
- **2.9B**：两个开关默认关闭且不可开启，旁注不兼容原因；若已开启参考时切换到 2.9B，自动关闭并提示。
- 开启参考时在区域内显示 PROMPT_GUIDE 要点提示（如"动作参考需写朝向""人物参考图建议中性站姿"）。

### 3.4 高级（默认折叠）

- 每次只生成**单张**（不提供批量数，batch_size 固定为 1；想多出几张就多次提交排队）。
- `seed`：随机 / 锁定（锁定时可手填，旁边有"使用上一张的种子"）。
- `sampler` / `scheduler`：下拉，默认"模型默认"。

### 3.5 生成流程

1. 点击「生成」或 Ctrl+Enter → 前端服务 `POST /api/jobs`（附带全部原始字段与参考图）。
2. 前端服务转发 painter `POST /v1/jobs`，同时登记待完成记录，并在**后台**跟踪任务直到结束 → 成功后写入图库（浏览器关掉也不丢记录）。
3. 页面每秒查询进度：阶段、步数、百分比、排队位置；可取消；可连续提交（排队）。
4. 错误码转中文提示（引擎未启动 / 显存不足 / 未检测到人物 / 模型不支持该参考 …）。
5. 当前表单自动保存到 localStorage，刷新不丢。
6. 失败（2026-10-15）：弹出提示（页面在后台时等切回来再计时，点提示可关）；结果条里的失败卡片保留，卡片右上角 ×、预览区错误条的「关闭」都能关掉，关掉后服务端也忘掉（`/dismiss`），刷新不再出现。以下情况也一律转为失败并提示，不会卡在「进行中」或「没有图也没有提示」：
   - 绘画模块重启过、任务已不在（painter 返回 404）；前端服务重启过、页面查不到任务（404）；
   - 成功但没有图片 / 写入图库出错（后端转失败；页面兜底：成功后 10 秒仍未写入图库）。
   - 绘画模块取结果前会等 ComfyUI 写好历史记录（ComfyUI 先发 `execution_success`、收尾后才写历史，紧接着读可能是空的，曾因此误报「ComfyUI 没有返回图片」）。
7. 结果条（预览区下方的缩略图条；人设页左栏的缩略条同样，2026-10-16）：缩略图固定高度、宽度随图片比例，整张图完整显示；条只能横向滚动。随时可按住左键左右拖动：内容超出时拖动即滚动，没超出时缩略图跟着走、松手弹回；拖动后松手不会选中图片。内容超出时鼠标放在上面转滚轮也是左右滚动（不滚动整页）。

## 4. 历史页 / 收藏页

### 4.1 记录存储

- `frontend/data/gallery.db`（SQLite），**每张图一条记录**：图片路径、种子、模型、steps、cfg、sampler、scheduler、宽高/比例、全部字段原值、LLM 描述文本、参考开关与参考参数、参考图引用、收藏标记、生成时间、job_id。
- 参考图存 `frontend/data/refs/`，以内容哈希命名，多条记录共享一份。
- 结果图仍在图片保存目录的 `<日期>\` 子目录（默认为程序根目录下的 `output\`，见 §10），由前端服务直接读取提供。
- 只收录通过本前端生成的图；文件被外部删除时显示"文件丢失"占位，可删除记录。

### 4.2 页面

- 按时间倒序网格，滚动加载；点击缩略图看大图（左右切换）。
- 每张图下方按钮：

| 按钮 | 行为 |
|---|---|
| 提示词 | 浮层显示正向/负向全文、各字段、模型/steps/cfg/种子/尺寸；一键复制 |
| 收藏 ☆/★ | 切换收藏；收藏页中取消收藏后该图移出收藏页（历史页仍在） |
| 删除 | 确认框 →**永久删除**原图文件与记录；无其他记录引用的参考图一并清理 |
| 复用设置 | 弹出三选一：**不含种子** / **连同种子** / **取消** |

- **不含种子**：恢复全部字段、模型、采样参数、尺寸、参考开关与参考图、LLM 描述 → 切回绘图页；种子设为随机。
- **连同种子**：同上，种子填入并锁定（每次只生成单张，种子与图一一对应，可直接复现）。
- 收藏页按钮与历史页完全一致。

## 5. 菜单页

左侧二级导航：**引擎**、**LLM**（以后的设置也加在这里）。

### 5.1 引擎

- 状态卡片：ComfyUI 进程状态（运行中 / 启动中 / 已停止 / 无响应）、版本、运行时长、GPU 与显存占用（`/system_stats`）、队列长度；painter 状态（只读）。
- 按钮：**刷新**、**启动**、**停止**、**重启**、**释放显存**。
- 页面打开时每 5 秒自动刷新。
- 有任务进行时停止/重启 → 确认框，确认后先取消任务。
- 启动/重启中按钮显示加载，健康检查通过后恢复；失败时显示日志末尾若干行。
- 显卡识别、显卡与 ComfyUI 版本不对应时的处理、「ComfyUI 启动参数」卡片见 §15。

### 5.2 LLM 配置

- 可添加多个**服务商卡片**：名称、格式（OpenAI 兼容 / Anthropic）、API 地址（选格式后预填官方地址，可改中转）、Token（密码框，保存后只显示首尾几位）。
- **获取模型**：前端服务调用 `GET {地址}/models`，列出模型 → 可搜索勾选列表；**仅勾选的模型**会出现在 AI 填写中。
- 每个勾选的模型：
  - **思考档位**：
    - Anthropic 格式：从模型能力信息（`capabilities.effort / thinking`）自动得出可用档位；不能关闭思考的模型不提供"不思考"。
    - OpenAI 格式：接口无能力信息，各家控制思考的参数也不同，按服务商选择「思考参数方式」（按 API 地址自动识别，可改）：
      - OpenAI 标准：`reasoning_effort`，档位 不思考(none) / low / medium / high
      - DeepSeek：`thinking.type` enabled/disabled + `reasoning_effort`，档位 不思考 / low / high / max（DeepSeek 默认开启思考，不发参数时并不会关闭）
      - 通义千问：`enable_thinking` true/false
      - 不发送：由模型默认
      接口不认这些参数（400）时自动改为不发送并重试。
  - **图片支持**：
    - Anthropic 官方：从 `capabilities.image_input` 自动读取（拉列表不消耗额度）。
    - 部分聚合平台返回 `architecture.input_modalities`，有则直接读。
    - 其余显示"未测试"，**只在点「测试」时**探测，不自动发请求。
  - **测试按钮**：一次请求同时验证文字连通 + 识图（发左右两半随机两种颜色的小图，两边都答对=支持；报错或答错=不支持，避免靠猜答对），显示耗时；结果保存，可手动修改。
- 存储：`frontend/data/settings.json`（本机明文）；浏览器拿不到完整 Token，所有 LLM 请求由前端服务发出。
- 调用方式：前端服务用 httpx 直接调用两种格式的接口（兼容中转），不额外安装 SDK。

## 6. LLM 辅助填写

### 6.1 卡片布局（绘图页顶部，可折叠）

```
┌ AI 填写 ────────────────────────────────────────────┐
│ 描述：[ 多行文本，中英文均可                           ] │
│ 参考图：[＋ 点击/拖入]  （仅多模态模型，1~3 张，仅作灵感）   │
│ 模型 [ ▼ ]  思考 [ 不思考 / low / … ▼ ]  安全 [ 不指定 ▼ ] │
│                          [ 撤销 ]  [ 修改 ]  [ 生成 ]    │
└─────────────────────────────────────────────────────┘
```

- 这里的参考图只发给 LLM，**不发给绘画模块**，与 §3.3 的人物/动作参考无关。
- 当前模型不支持图片或未测试时，上传框置灰并说明原因。

### 6.2 生成与修改

| | 生成 | 修改 |
|---|---|---|
| 输入 | 描述 + 卡片参考图 + 已开启参考的图 | 同左 + **当前全部字段值** |
| 结果 | 重新生成全部字段（待确认 #1） | 在现有内容基础上按描述做针对性修改 |
| 涉及字段 | `quality_meta_year_safe`、`aspect_ratio`、`count`、`character`、`series`、`artist`、`appearance`、`action`、`nltags`、`neg` | 同左 |
| 不涉及 | steps、cfg、seed、模型等采样参数 | 同左 |

- 结果直接写入字段，变化字段短暂高亮；「撤销」一键恢复到 LLM 改动之前。
- 等待中显示加载，可取消。
- 输出：要求 LLM 返回字段 JSON（键名 = 统一字段名）；支持结构化输出的接口用结构化输出，否则靠提示词约束 + 容错解析。

### 6.3 安全等级

| 选择 | 规则 |
|---|---|
| 不指定 | LLM 自行判断，`quality_meta_year_safe` 中必须恰好一个安全词 |
| safe / sensitive / nsfw / explicit | 必须使用所选等级，排除另外三个 |

`neg` 中加入与所选等级相反的约束。返回后前端再校验：剔除多余安全词。

### 6.4 其他输出校验

- `artist` 每项须以 `@` 开头；仅当描述明确提到画师或画风时填写，否则置空。
- `aspect_ratio` 不在预设列表中则忽略，保留原值。
- 多余的键忽略，缺失的键在「修改」模式下保持原值。

### 6.5 与人物/动作参考联动

已开启参考且已上传图片时，「生成/修改」会先让识图模型**逐张描述**这些图片，再把描述按图片分别标注后交给生成（2026-10-12 起，见 §12），规则来自 `painter/PROMPT_GUIDE.md`：

- **人物参考图**：`count` 与参考人物一致；`appearance` 只写 2~5 个核心特征，不写冲突特征；描述要求换装时，在 `neg` 写原服装标志部件。
- **动作参考图**：`action` 写与图一致的动作词，**必须写朝向**（如 `facing viewer`）；构图与骨架范围一致（全身 `full body` / 半身 `upper body`）。
- **两者同开**：同时满足以上两条。

### 6.6 识图模型看不到图时（或识图失败）

| 情况 | 卡片内黄色提示 | LLM 行为 |
|---|---|---|
| 动作参考已开 | "当前模型看不到动作参考图：请在描述中写明动作（含朝向、全身/半身），或让 action 留空" | 描述写了动作 → 整理成 `action` 并补全朝向/构图；没写 → `action` 留空，不猜测 |
| 人物参考已开 | "当前模型看不到人物参考图：请在描述中写核心特征，或让 appearance 留空" | 只用描述中的特征；没写 → `appearance` 留空 |

### 6.7 提示词文件（全部独立，便于微调）

代码中不写死任何发给 LLM 的文字，全部在 `frontend/prompts/`，按用途分文件夹（详见 `prompts/README.md`）：

```
prompts/
├─ fill/                 「AI 填写」：绘画提示词字段的生成 / 修改
│  ├─ system/            系统提示词片段：system、fields、mode_generate / mode_modify、
│  │                     safety_fixed / safety_auto、user_images、ref_character(_noimage)、
│  │                     ref_pose(_noimage)、ref_both
│  ├─ user/              用户消息：user_message.md（描述模板）、labels.json（图片标注）
│  └─ schema.json        输出 JSON 结构
└─ test/probe.md         其它：「测试」按钮的识图问题
```

- **组装**：系统消息 = system + fields + 模式片段 + 安全片段 + 所需参考片段；用户消息 = 描述 + 当前字段（修改）+ 带标注的图片。占位符：`{{safety}}`、`{{current_fields}}`、`{{description}}` 等。
- **热加载**：每次请求重新读取，修改后无需重启。
- **调试**：每次请求完整内容写入 `logs/llm_last_request.json`（图片只记尺寸，不存 base64），页面不显示。
- 发给 LLM 的图片先压缩到长边约 1500px。

报错没点名取值（接口不认整个思考参数）时不去掉档位，只是这次不发送思考参数。
档位被改掉时，AI 填写 / 人设 AI / 「测试」按钮会提示「不支持思考强度 X，已自动改用 Y」，绘图页的思考下拉框随之刷新。

菜单 → LLM 的每个服务商可折叠（点名称或 ▸/▾；标题栏有「全部折叠 / 全部展开」）；折叠状态记在浏览器本地，

### 9.7 匹配：模糊、造型变体、多变体、画师（2026-10-17）

起因：「画一个睡衣优香」识别结果是「优香 / hayase yuka」（睡衣被当成服装去掉），「优香」在名称映射里精确命中本体，变体根本没参与；
角色库 / 人设导入的模糊搜索拿整段「睡衣优香」去 Danbooru 查，0 个结果（别名写的是「早濑优香(睡衣)」）。

| # | 问题 | 结论 |
|---|---|---|
| 1 | 识别角色 | 识别结果加 `outfit`（服装原文，如 睡衣 / 运动服）；`name` 只写角色名；同一角色不同服装各列一项（最多 4 项）。`search/extract_*` |
| 2 | 查角色库 | 名称映射精确命中 → **本地模糊比对**（中日文：输入的每个字都出现在某个名字里；英文：输入是名字的一部分；反过来名字包含在输入里也算但优先级低），核对作品 → Danbooru。字字对上的写法记进名称映射，下次直接命中 |
| 3 | 认变体 | 找到本体后，拿 `outfit` 和各变体的「服装词」比对：标签多出的括号（pajamas）、名称括号里的（睡衣、体操服）、名称映射去掉本体名剩下的（パジャマ）。没给 `outfit` 时看描述里这个角色所在的那一句（按标点和「和 / 与」分句；同一角色出现多次时不看）。对上就用变体 |
| 4 | 对不上 | 资料块附「可选的造型变体」（标签（名称）：特有服装标签），由填写的 LLM 按意思判断（运动服 ≈ 体操服）。`fill/user/character_item.md` + `fill/system/web_character.md` |
| 5 | 多个变体 | 同一角色的不同造型各留一条（按最终标签 + 没对上的服装去重）；规则：character 逐个写、count 按人数、appearance 含各自服装、nltags 逐个写清。人设同理（`fill/system/persona.md`） |
| 6 | 人设匹配 | 已有角色的人设，另外认角色库里这个角色（本体与变体）的全部名称；识别出的角色名与人设模糊比对（字字对上 + 作品对得上）也算命中 |
| 7 | 全角 / 半角 | 角色、画师、人设名的比较统一 NFKC + 不分大小写（Ｋ子 = K子 = k子）；启动时把已存的名称映射按新规则重算 |
| 8 | 画师 | 名称映射没命中时做「包含」比对（「K子老师」→ K子）；Danbooru 同名多个时画师库里已有的优先 |
| 9 | 模糊搜索 | 先列角色库里模糊比对上的（标「已在角色库」），再接 Danbooru；Danbooru 整段查不到时把名字拆两段、两种顺序再查（`*优香*睡衣*`）；连不上时只给角色库的结果 |
| 10 | artist 输入框 | 绘图页 artist 与人设页「画师偏好」：按正在输入的那一段从**画师库**给下拉候选（名称 · @标准标签 · 对上的别名 · 图片数，↑↓ 回车或点击替换），不联网；画师库没有时提示「去 菜单 → 画师库 添加」。框里能对上画师库、但不是标准标签的写法（@k子）在框下提示「k子 是 K子 → @courreges ace 替换」 |

- AI 填写「参考资料」里角色一行标出服装（「穿睡衣」）、「造型变体」，以及「没对上变体」（附了可选变体，交给 AI 判断）。
- 接口：`POST /api/library/artists/resolve`（`names` → 能对上画师库的非标准写法）。

## 10. 存储（2026-10-11 新增）

菜单 → 存储：设置图片保存目录（data/settings.json 的 `storage.output_dir`，留空 = 绘画模块默认：程序根目录下的 `output\`）。
- 保存时校验：必须是绝对路径；不存在则创建；做一次写入测试。
- 前端服务启动绘画模块时传入环境变量 `PAINTER_OUTPUT_DIR`；保存后自动重启绘画模块，有任务时先确认并取消任务。

## 11. 人设（2026-10-11 新增）

顶栏「人设」页：以卡片展示人设。人设 = 自己编辑的原创角色，或从 Danbooru 导入的已有角色；内容是 **基础外观 + 服装差分（造型）**。

### 11.0 已确认的决定

| # | 问题 | 结论 |
|---|---|---|
| 1 | 基本信息字段 | 名称、别名、「原创人物」开关、角色标签、作品、主体、**画师偏好**、**分组**；不做 NSFW 标记 |
| 2 | 预览图 | **不进历史 / 收藏**，只在人设页管理 |
| 3 | AI 填写的人设匹配 | 加开关「人设匹配」，**默认开启** |
| 4 | 角色库 | 只存 Danbooru 上的已有角色，去掉「手动新增」；原创统一放人设 |
| 5 | 第一版范围 | 含 AI 整理；「按关键词补造型」放第二批（未做） |
| 6 | 新建 | 只有「＋ 新建人设」，**默认原创人物**；已有作品的角色自己关掉开关（用 🔍 Danbooru 导入时自动关掉） |
| 7 | 原创人物的名称 | 不进 character：**代码层**从 AI 填写结果里去掉（不靠提示词）。只对人设库里打开「原创人物」开关、且本次命中的人设生效；只处理 character，作品 `original` 保留；角色库 / 联网检索 / Danbooru 数据不做任何处理 |

### 11.1 列表

搜索（名称 / 别名 / 角色标签 / 作品 / 分组）、类型筛选（全部 / 原创 / 已有角色）、分组筛选；「＋ 新建人设」（默认原创人物，已有作品的角色关掉「原创人物」再用 🔍 Danbooru 导入）。
卡片：2:3 封面（无封面显示首字）、名称、类型、作品、造型数、分组。

### 11.2 详情（两栏）

- **右栏**：
  - 基本信息：名称*（全库唯一，旁边「🔍 Danbooru」）、别名（同样参与匹配；名称与别名全库不能重复）、「原创人物」开关（标题栏右侧，默认开；关 = 已有作品的角色，从 Danbooru 导入时自动关；打开时清空作品）、角色标签（写进 character）、作品（写进 series；原创人物不预填、输入框置灰）、主体（写进 count）、画师偏好（自动补 @，未指定画师时使用）、分组（点已有分组快速添加）。
  - 基础外观：基础标签（只写本体特征）、外观描述（中文，随人设资料发给 LLM）；AI 给出的「未归类标签」以候选显示，点击加入基础标签或某套造型。
  - 服装差分：每套 = 名称、默认（单选）、标签、中文描述、专属角色标签（可选，Danbooru 造型变体标签，选用这套造型时替换 character）；可增删、上下移动。
  - AI 助手：补充描述 + 参考图（多模态模型才发送）+ LLM + 标签参考 →「AI 整理」；结果可撤销，需点「保存」。
  - 顶部：返回（有未保存修改时确认）、填入绘图页、删除、保存（Ctrl+S）。
- **左栏**：
  - 图片：封面 + 预览图（左右切换、缩略条、点击看大图）；操作：设为封面 / 复用到绘图页（不含种子 / 连同种子）/ 用它的提示词 / 删除这张（永久删除）。封面可拖入或粘贴图片、「上传封面」「从历史选图」。
  - 生成预览：造型、模型、比例、分级、画师 + 自动组合的提示词（改右栏字段会同步；手改后显示「恢复自动组合」）→「按当前提示词生成预览」，进度显示在左栏，可取消。
  - 固定部分在 `config/defaults.json` 的 `persona_preview`：quality（后面接所选分级）、composition（默认 `solo, cowboy shot, looking at viewer, simple background`，紧跟在主体后面）；负向提示词用默认 neg；steps / cfg 用所选模型默认值；种子随机。
  - 预览前若有未保存的修改，会先自动保存。

### 11.3 已有角色：Danbooru 检索 + AI 拆分

1. 「🔍 Danbooru」：两个选项——「直接搜索」按名称 / 角色标签查 `/autocomplete.json`（中日文名、别名都能命中）；「模糊搜索」名字 + 作品（同 §9.6）。候选标出「已在角色库」。
2. 选中候选后查 **造型变体标签**（`/tags.json` 按 `基名_(*)_(作品)` 匹配，如 `aris (maid) (blue archive)`；排除 0 张图与 cosplay 标签），最多勾选 6 个。
   本体在角色库且存过变体列表时直接用（显示「列表来自角色库，更新于 …」与「更新列表」）；已存入的变体标「已在角色库」。
3. 「导入」：角色库有缓存时只联网取一次共现标签（100 个），失败则用缓存；没有则完整检索并**存入角色库**。
   勾选的变体同一规则：有缓存只联网取一次共现标签（失败用缓存），没有则完整取并存入角色库（挂在本体下）；没勾选的变体按 §9.6 在后台缓存。
4. 单独调用一次 LLM 拆分（`prompts/persona/split_*`）：中文名、主体、基础标签、外观描述、造型（默认造型 + 每个勾选的变体，变体标签写进专属角色标签）、未归类标签。
   代码校验：造型标签去掉与基础标签重复的；专属角色标签只能是勾选的变体（LLM 编造的清空）；默认造型恰好一个；LLM 漏掉的变体按该变体 ≥30% 的共现标签自动补一套（去掉角色本体 ≥50% 的标签）。
5. 结果写进编辑页（不自动保存），已有内容时选「覆盖 / 保留已有内容」，可撤销。别名取 Danbooru 的 other_names（单个英文词如 aris / alice 太常见，不收）。
6. 关闭「AI 拆分」（或没有配置 LLM）时：只导入角色标签、作品、别名与变体造型，共现标签（≥10%）全部放进未归类。

### 11.4 原创：AI 整理

`prompts/persona/refine_*`：发送当前人设（JSON）+ 补充描述 +（可选）参考图 +（可选）标签参考（DanbooruSearch，结果缓存）；返回完整的基础标签 / 外观描述 / 造型。
没提到的部分保持原样；专属角色标签只能沿用原值；按名称保留原造型 id。

### 11.5 用到绘图

| 入口 | 行为 |
|---|---|
| 人设页「填入绘图页」 | 用左栏选中的造型填 count / character（造型有专属角色标签时用它）/ series / appearance（= 基础标签 + 造型标签）；artist 为空时填画师偏好；其它字段不动；切到绘图页 |
| 绘图页 character 旁「从人设选择」 | 选人设 → 选造型（或「仅基础外观」），填法同上 |
| AI 填写「人设匹配」（默认开） | 描述中出现名称 / 别名（英文按整词匹配）→ 本地匹配，不联网、不额外调用 LLM；另外「填入绘图页 / 从人设选择」会记下选用的人设（AI 卡片里显示，可 × 取消），一并附上并标出当前造型。资料块见 `prompts/fill/user/persona_*`，规则见 `prompts/fill/system/persona.md`；已由人设覆盖的角色不再联网检索。参考资料区显示命中的人设，可「打开人设」。命中**原创人物**时，代码层把其名称 / 别名（忽略大小写、空格与括号后缀，如「天童爱丽丝 (original)」）从 character 去掉并提示；人设里手填的角色标签保留 |

### 11.6 存储

- `data/personas.db`（personas 表，造型 / 别名 / 分组为 JSON 列）。
- 封面复制到 `data/personas/<id>/cover.png`（**原图无损、不缩小**，只存像素、不带原图的文本块）与 `cover_thumb.webp`（480，列表用），删除预览图或历史图后封面仍在。2026-10-14 前的版本存的是 `cover.webp`（长边 1280、有损 q90）：启动时自动迁移一次，来源生成记录的原图还在的用原图重建 `cover.png`；上传的封面或原图已删除的保持 webp（仍可读取），重新设一次封面就换成 PNG。
- 预览图是普通生成记录：`gallery.db` 的 `images.persona_id` 列（旧库启动时自动补列）；`/api/gallery` 排除这些记录，绘图页的任务列表也不显示人设预览任务。
- 删除人设：删除资料、封面与该人设的全部预览图（预览图不在历史页，留着就再也看不到了）。

## 12. 识图（2026-10-12 新增）

原来上传的图片和描述、各种规则一起放进同一次请求，模型要边看图边写标签，细节容易漏。改为两步：

```
① 识图：上传的图片（灵感图、已开启的人物参考图 / 动作参考图）逐张单独请求识图模型，按用途详细描述（并行，prompts/vision/）
② 生成：描述原文整理成「识图结果」块（prompts/fill/user/vision_*.md）放在用户消息最前面，正式填写只收文字、不再收图片
```

### 12.0 已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 识图用哪个模型 | AI 填写卡片新增「识图模型」下拉：默认「同上」（AI 填写的模型和思考档）；可单独选一个能看图的模型（用它在菜单 → LLM 里的默认思考档）。生成用的模型不必能看图 |
| 2 | 第二步要不要附原图 | 不附，只发识图文字 |
| 3 | 适用范围 | 只改绘图页 AI 填写；人设页 AI 整理不变（参考图仍直接发给模型） |

### 12.1 细节

- 每种用途一份提示词：灵感图全面描述；人物参考只重外观；动作参考只重姿势（照片 / 骨架图分开，骨架图附 OpenPose 配色与朝向判断提示）。输出中文，按 `【小节】` 分段，能对应 Danbooru 标签的细节在括号里附英文标签，看不清的写「无法判断」。
- 识图与「识别角色 / 标签参考」并行；单张识图出错按 `retry.py` 自动重试，仍失败只提示，这张图按「看不到图」处理（用 `*_noimage.md`）；没有描述且全部失败时报错，不做正式填写。
- 识图结果按「图片 + 用途 + 模型与思考档 + 提示词内容」缓存在内存（最多 64 条，重启清空）：反复点「填写 / 修改」不重复识图，改了 vision/ 提示词会自动重新识图。
- 识图模型下拉只列出能看图的模型；选过的模型被取消勾选或测出不能看图时自动回到「同上」。灵感图上传框、「看不到参考图」提示都按识图模型判断。
- 识图模型下拉旁的「重新识图」（2026-10-16）：开启后下一次「填写 / 修改」不读缓存、全部图片重新识图，新结果替换缓存；只管这一次，成功后自动关闭（失败或取消时保持开启），不保存到表单。没有要识图的图片时不可点。
- 卡片下方新增可折叠的「识图结果」，逐张显示识图原文、耗时或「缓存」、失败原因；日志 `llm_last_request.json` 记在 `recognition`。

`/api/llm/fill` 新增可选参数 `vision_provider_id`、`vision_model_id`（不传 = 同上）、`vision_no_cache`（true = 这次不用识图缓存，日志 `recognition.no_cache`），响应新增 `recognition: {model, items: [{label, kind, text, error, cached, elapsed}]}`。

## 13. 人设卡（2026-10-14 新增）

把人设导出成一张 PNG 图片分享；图片里带着人设的完整资料，拖进人设页即可导入。

### 13.0 已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 卡面样式 | **纯封面图**：卡面就是封面原图，不加任何文字；没有封面时生成占位图（渐变底 + 首字 + 名称 + 「Anima Studio · 人设卡」） |
| 2 | 导入后 | **直接保存**（含封面），可一次导入多张；只导入一张时自动打开它的详情页 |
| 3 | 重名 | **每次询问**：覆盖 / 另存为新人设（自动改名「名称 (2)」）/ 跳过；批量时可勾选「后面再遇到重名也这样处理」 |
| 4 | 附加功能 | 批量导出（zip）、拖入导入、兼容 SillyTavern 角色卡 |
| 5 | 封面副本 | 改为无损 PNG、不缩小（见 §11.6），人设卡反复转手画质不变 |

### 13.1 格式

- PNG 的 iTXt 文本块，关键字 `anima_persona`，zlib 压缩，内容为 JSON：
  `{"format": "anima-studio/persona", "version": 1, "app", "exported_at", "has_cover", "persona": {…}}`
  另写 `Title`（人设名称）与 `Software`（Anima Studio）。
- `persona` 含：名称、别名、原创 / 已有（`kind`）、角色标签、作品、主体、画师偏好、分组、基础标签、外观描述、全部造型（含专属角色标签）、Danbooru 来源；**不含**本机 id、封面来源记录、预览图。
- `has_cover = false`（占位图）时导入不设封面；覆盖已有人设时保留它原来的封面。
- 卡面 = 封面原图，不缩小：封面副本是 PNG 时直接用它；旧版 `cover.webp` 且来源生成记录的文件还在时用那张原图，否则用 webp。原图的文本块（生成参数等）不会带进卡里。
- 聊天软件压缩图片会丢掉文本块：分享要用「原图」或文件方式发送。没有数据的图片导入时会说明这个原因。

### 13.2 导出

- 详情页顶部「导出人设卡」：有未保存的修改（或尚未保存）时先自动保存，再下载 `人设卡_<名称>.png`。
- 列表页「导出全部」/「导出筛选结果（N）」：按当前搜索 / 类型 / 分组导出 zip（`人设卡_<日期时间>.zip`，每个人设一张 `<名称>.png`）。

### 13.3 导入

- 列表页「导入人设卡」（可多选），或把文件直接拖到列表页；导出的 zip 在页面里解开（只取 PNG）。
- 卡里的数据按类型逐项取值、限制长度，再经过人设保存时的同一套规范化；造型 id 只保留字母数字。
- 重名：卡的名称与已有人设的名称或别名相同即视为重名。卡里的别名若已被其它人设用作名称 / 别名，导入时去掉并提示。
- 覆盖：资料全部换成卡里的（含分组），卡里有封面时封面也换掉；已有预览图保留。
- SillyTavern 角色卡（tEXt `ccv3` / `chara`，V1 / V2 / V3）：只取名称与描述（`{{char}}` 换成名称）建原创人设，描述放进外观描述，卡面作封面，附一套空的默认造型；提示可用「AI 整理」生成标签。
- 导入多张时，有失败 / 改名 / 去掉别名等情况会弹出逐张结果，否则只提示数量。

### 13.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/personas/{id}/card` | 导出一张人设卡（PNG，`Content-Disposition` 带中文文件名） |
| GET | `/api/personas/export.zip?q=&kind=&group=` | 按列表筛选条件批量导出 |
| POST | `/api/personas/cards/import` | `{data: PNG 的 data URL, on_conflict: ""\|overwrite\|rename\|skip}`；重名且未给 `on_conflict` 时返回 409 `NAME_CONFLICT`，`detail` 含 `conflict`、`suggested_name`；成功返回 `{status: created\|overwritten\|skipped, persona, source: anima\|sillytavern, renamed_from, dropped_aliases, notes}` |

## 14. 图片里的生成参数与「从图片读取」（2026-10-14 新增）

### 14.0 已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 读取优先级 | 先读 `anima_painter`，其次 A1111 `parameters`（PNG 文本块 / JPEG、WebP 的 EXIF UserComment）、ComfyUI `prompt` 工作流、NovelAI `Comment` |
| 2 | 种子 | 读本程序的图时可选「保持相同种子」（勾选状态记在浏览器本地）；其它来源的图只读提示词 |
| 3 | 参考图 | 本机图库有这张图的记录（按 job_id）时等同「复用」，参考图一并恢复；没有记录（别人的图）时提示参考图不在图片里，参考开关关闭 |
| 4 | 其它来源的拆分 | AI 拆分（用 AI 填写卡片选的模型）或按规则拆分，可在弹窗里选，选择记在浏览器本地；没有 LLM 时只能规则粗分 |
| 5 | 旧图迁移 | 启动时后台自动执行一次（完成后留标记 `data/image_meta_v2.done`）；菜单 → 存储 可手动「补写缺少的」（原名「补写旧图」）/「全部重写」 |

### 14.1 写入格式

绘画模块保存 PNG 时写两个文本块（`painter/painter/images.py`）：

- `anima_painter`（JSON）：`{format: "anima-studio/image", version: 2, job_id, params, prompt: {positive, negative}, form}`。
  `params` 是绘画模块实际使用的参数（含种子）；`form` 由前端通过 `client_meta.form` 传入（`server/imagemeta.py` 的 `form_subset`）：
  各字段原值、画幅、宽高、采样器 / 调度器选择、参考设置（人物参考只记张数，不含参考图；动作参考不含图）。不含 AI 描述与人设。
  2026-10-14 前的 v1 只有 `params`、`prompt`、`job_id`。
- `parameters`（A1111 格式）：`正向\nNegative prompt: 负向\nSteps: …, Sampler: …, Schedule type: …, CFG scale: …, Seed: …, Size: WxH, Model: …, Version: Anima Studio`。
  采样器写 ComfyUI 的名字。前端迁移用同一写法（`imagemeta.a1111_text`），改动要两边同步。

### 14.2 从图片读取（绘图页）

参数栏顶部「从图片读取提示词」：点击选择、选中后 Ctrl+V 粘贴，或把图片拖到参数栏任意位置（落在参考图 / 灵感图上传框里的仍归上传框）。弹窗显示来源、正 / 负向提示词、参数与选项：

| 图片 | 应用后 |
|---|---|
| 本程序生成，本机图库有记录 | 同「复用」：字段、模型、采样参数、画幅、参考开关与参考图、AI 描述 |
| 本程序生成（v2），本机没有记录 | 字段、模型（本机没有时用默认模型并提示）、steps / cfg / 采样器 / 调度器、画幅；参考开关关闭，原图用了参考时提示 |
| 本程序生成（v1），本机没有记录 | 整段提示词按所选方式拆到字段，其余同上 |
| 其它工具 | 只把提示词拆到各字段（覆盖全部字段），模型、采样参数、画幅、种子不动 |

- **AI 拆分**：`prompts/import/`，只分类不改写；代码校验原文每个标签都出现在某个字段里，漏掉的补进 appearance / neg 并提示；artist 补 @。出错自动重试同 AI 填写，弹窗关闭即取消。
- **按规则拆分**（原「规则粗分」）：质量 / 年份 / 安全 / score 词 → quality_meta_year_safe；`1girl`、`solo`、`no humans` 等 → count；`@xxx`、`artist:xxx` → artist；第一个「名字 (作品)」→ character；5 个词以上的长句 → nltags；其余 → appearance；负向 → neg。
- 没有参数时提示「聊天软件或网站压缩过的图片会丢掉参数，请用原图」。

### 14.3 旧图迁移

按图库记录（历史、收藏、人设预览）给还在的 PNG 补写 v2 `anima_painter` 与 `parameters`：`form` 来自记录的表单；图片里已有 v1 块时沿用其中更全的 `params`（model_file、stages）。
只替换这两个文本块（放在 IHDR 之后），其它块逐字节原样保留并校验；先写临时文件再替换，保留修改时间。已是 v2 的跳过（「全部重写」时也重写）；文件被占用等失败的记在 `logs/frontend.log`，标记不写，下次启动重试。

### 14.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/image-meta/read` | `{data: 图片 data URL}` → `{source: anima\|a1111\|comfyui\|novelai, source_label, positive, negative, seed, …}`；anima 另有 `version`、`job_id`、`params`、`form`、`record`（本机图库记录，没有为 null）；其它来源另有 `info`（原图参数）。没有参数时 422 `NO_METADATA` |
| POST | `/api/image-meta/split` | `{mode: ai\|rule, positive, negative, provider_id, model_id, level, request_id}` → `{fields, warnings, elapsed}` |
| POST | `/api/image-meta/migrate` | `{force}` → `{total, updated, skipped, missing, unsupported, failed}` |

代码：`server/imagemeta.py`、`server/llm/imgsplit.py`、`web/js/imgread.js`。

## 15. 显卡识别与 ComfyUI 启动参数（2026-10-14 新增）

支持 AMD 显卡：同一套程序，启动 ComfyUI 前自动识别本机显卡和装的 ComfyUI 便携版是哪一版。AMD 部分未实测（作者只有 NVIDIA 显卡）。

### 15.0 已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 是否单独出 AMD 版 | 不单独出：代码与 `start.bat` 只有一份，只有 ComfyUI 便携版按显卡下载不同的包（`ComfyUI_windows_portable_nvidia.7z` / `_amd.7z`，解压后目录名相同） |
| 2 | AMD 默认启动参数 | 不加，与官方 AMD 便携版的 `run_amd_gpu.bat` 一致 |
| 3 | 额外启动参数 | 菜单 → 引擎 加「ComfyUI 启动参数」输入框，NVIDIA 也可用 |
| 4 | 不做 | 自动下载 ComfyUI、ZLUDA / DirectML、Intel 显卡；单独运行的 `painter\start_comfyui.bat` 不做识别、不读启动参数 |

### 15.1 识别

- **本机显卡**：PowerShell `Get-CimInstance Win32_VideoController` 的 PCI 厂商号（`10DE` NVIDIA、`1002` AMD、`8086` Intel），进程内只查一次。
  有 NVIDIA 就按 NVIDIA（笔记本常见核显 + NVIDIA 独显），其次 AMD。查询失败时不判断。
- **ComfyUI 版本**：读便携版 `python_embeded\Lib\site-packages\torch\version.py` 的 `cuda` / `hip`（`rocm`）/ `xpu` 字段，不启动 Python。读不到时不判断。
- 引擎页 ComfyUI 卡片显示「显卡」（ComfyUI 实际会用的那块）与「ComfyUI 类型」（NVIDIA 版 / AMD 版 / 未安装）；控制台启动时打印一行同样的信息。

### 15.2 启动前检查

| 情况 | 处理 |
|---|---|
| 没有 `ComfyUI_windows_portable\python_embeded\python.exe` | 不启动，按识别到的显卡说明该下载哪个包 |
| 显卡与版本明确对不上：装的是 NVIDIA 版，本机有 AMD 显卡、没有 NVIDIA 显卡（或反过来） | 不启动，说明该换哪个包、换之前把模型移出来、换好后重装节点与依赖。引擎页提供「仍然启动」（跳过检查，防止识别有误时无法使用） |
| AMD 版 + 本机同时有 NVIDIA 显卡（AMD 核显 + NVIDIA 独显） | 照常启动，提示建议换成 NVIDIA 版 |
| 装的版本对应的显卡没检测到，也没有另一家的显卡（如只有 Intel 核显） | 照常启动，提示可能无法启动 |
| CPU 版 / Intel 版 | 照常启动，提示出图很慢 / 未在 Intel 显卡上测试 |

- 被拦下时状态为「已停止」，`blocked: true`，`error` 为原因；顶栏显示「引擎未启动 · 原因见 菜单 → 引擎」。端口上已有在运行的 ComfyUI 时照常接管，不做检查。
- 生成时显存不足（`OUT_OF_MEMORY`）且装的是 AMD 版、启动参数里还没有 `--enable-dynamic-vram`：错误提示后面追加「可在启动参数里加 --enable-dynamic-vram」。

### 15.3 启动参数

- 保存在 `data/settings.json` 的 `engine.comfy_args`，启动 ComfyUI 时追加在命令行最后（同时写进 `logs/comfyui.log`），重启 ComfyUI 后生效。
- 按 Windows 命令行规则拆分，引号可包住含空格的路径；`--listen`、`--port` 由本程序固定，不能填。
- ComfyUI 运行中且正在用的参数与设置不一致（外部启动的进程：设置了参数就算）时提示「重启后生效」。
- 卡片放在引擎页最下面，**默认折叠**（2026-10-17）：只显示当前参数（或「未加参数」）和一句提示，点标题展开输入框与说明；有没生效的修改时折叠状态也提示。

### 15.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/system/status` | `comfyui` 新增 `blocked`、`gpu: {gpus, vendor, gpu_vendor, gpu_names, comfy: {installed, flavor, torch}, level: ok\|warn\|block, reason: missing\|mismatch, message, oom_hint}`、`args: {comfy_args, pending_restart, external}` |
| POST | `/api/system/comfyui/{start\|restart}?ignore_gpu=1` | 跳过启动前检查（引擎页「仍然启动」） |

代码：`server/engine.py`、`server/procs.py`（`Service` 的 `args_fn`、`check_fn`）、`web/js/menu.js`（引擎页）。
